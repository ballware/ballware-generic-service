# ballware Generic Service — documentation

This folder documents the Generic Service (the generic data engine) from the backend side: its HTTP
API surface, request/response payloads, the metadata-driven semantics behind those payloads,
tenancy and authorization behavior, and the OpenAPI snapshots the pages are derived from.

> Scope note: this is the **backend view** of the generic data engine. The frontend consumption
> contract (how entity/query/state metadata is interpreted by the UI framework) lives in
> `ballware-angular/docs/metadata`, and the metadata authoring model (entities, queries, lookups,
> statistics, states, pages as documents managed by the meta service) lives in
> `ballware-meta-service/docs`. Neither is duplicated here.

## Quick facts

- **Four OpenAPI documents** (all OpenAPI `3.0.4`, `src/Ballware.Generic.Service/Startup.cs:413-435`):

  | Document | Title | Paths | Schemas | Raw JSON URL |
  | --- | --- | --- | --- | --- |
  | `generic` | ballware Generic API | 13 | 3 | `/swagger/generic/swagger.json` |
  | `meta` | ballware Generic Meta API | 12 | 1 | `/swagger/meta/swagger.json` |
  | `service` | ballware Service API | 3 | 3 | `/swagger/service/swagger.json` |
  | `schema` | ballware Schema API | 4 | 2 | `/swagger/schema/swagger.json` |

  SwaggerUI endpoint registration: `src/Ballware.Generic.Service/Startup.cs:523-526` (only when
  `Swagger.EnableClient`).
- Committed snapshots: [openapi/generic.json](openapi/generic.json),
  [openapi/meta.json](openapi/meta.json), [openapi/service.json](openapi/service.json),
  [openapi/schema.json](openapi/schema.json), provenance in
  [openapi/manifest.json](openapi/manifest.json), generated by
  [openapi/fetch-spec.sh](openapi/fetch-spec.sh).
- **32 mapped HTTP operations** across seven route bases plus the MCP endpoint
  (`src/Ballware.Generic.Service/Startup.cs:490-498`).
- **Authentication**: JWT bearer against an OIDC authority
  (`src/Ballware.Generic.Service/Startup.cs:175-189`); **authorization** by scope → policy
  (`metaApi`, `serviceApi`, `schemaApi`, `genericApi`; `src/Ballware.Generic.Service/Startup.cs:192-219`).
  `genericApi` and `metaApi` are **identical policies** — both compare the `scope` claim against
  `Authorization.RequiredMetaScope`, so the Generic API is authorized by the `metaApi` scope value.
- **Development port**: HTTP `http://localhost:5002` (Kestrel endpoint in
  `src/Ballware.Generic.Service/appsettings.Development.json:8-14`). This repository has no compose
  file; the external `ballware-docker-compose` deployment publishes the same port (`5002:5002`) and
  sets `Kestrel__Endpoints__Http__Url=http://+:5002` inside the container.
- **MCP endpoint**: mounted at `/generic/mcp` when `Mcp.Enabled`
  (`src/Ballware.Generic.Service/Startup.cs:505-511`), authenticated with a user JWT whose scope
  must contain `Mcp.RequiredMcpScope` (defaults to `Authorization.RequiredMetaScope`,
  `src/Ballware.Generic.Service/Startup.cs:130-136`). Not part of any OpenAPI document — see
  [concepts/mcp-endpoint.md](concepts/mcp-endpoint.md).
- JSON bodies and POCO response bodies are **PascalCase** (`PropertyNamingPolicy = null`,
  `src/Ballware.Generic.Service/Startup.cs:234-242`); rows returned from tenant SQL keep the SELECT
  alias casing instead. See [api/README.md](api/README.md#payload-conventions).

## Request flow

```text
client (browser app / other service / AI agent)
  |  Authorization: Bearer <token>   (scope claim: metaApi | serviceApi | schemaApi)
  v
ASP.NET Core routing + JWT bearer authentication          Startup.cs:175-189
  |  scope claim -> policy "genericApi" / "metaApi" /     Startup.cs:192-219
  |              "serviceApi" / "schemaApi"
  v
minimal-API endpoint handler                              Startup.cs:490-498
  |  tenant from the "tenant" claim  (generic, lookup-user,
  |  processingstate, statistic routes)
  |  or explicit {tenantId} path segment (service, schema routes)
  v
metadata resolution via IMetadataAdapter                  Startup.cs:327-329
  |  tenant + entity/lookup/statistic metadata from the
  |  meta service  -> 404 "Unknown tenant or entity" style bodies
  v
rights evaluation (tenant + entity right, Jint scripts)   Startup.cs:332-334
  |  candidate "<application>.<entity>.<right>"
  |  -> 401 empty when refused
  v
tenant provider (mssql | postgres, Dapper)                Startup.cs:337-398
  |  metadata SQL with [ballwareschema] + @tenantId/@tenant_id
  |  + @claim_<claimtype> + @param bindings
  |  + Jint entity/statistic scripts                      Startup.cs:332-333
  v
external platform services with client-credentials tokens Startup.cs:254-317
     meta service (metadata, jobs, exports) · storage service (import/export files)
     ML service (predictions)
  v
Quartz scheduler (import jobs, clustered job store)       Startup.cs:251-252
```

For setup, configuration, build and test commands see the repository
[README.md](../README.md). For OpenAPI regeneration see
[openapi/README.md](openapi/README.md).

## Consumption notes (for `ballware-docs`)

- Plain Markdown only: relative links, tables, fenced code blocks, ASCII diagrams. No MDX, no
  frontmatter, no Docusaurus-specific directives — the pages are importable as static content.
- Every documented path exists in the committed snapshots. The snapshots in `openapi/` are the
  **canonical** API surface; the prose pages explain payload semantics that OpenAPI cannot express
  (metadata-derived row shapes, identifier/rights coupling, job state machines).
- Snapshot provenance (tool + version, environment, `git describe`, `fetchedAt`, per-document
  counts) is in [openapi/manifest.json](openapi/manifest.json).
- If `ballware-docs` keeps fetching live specs instead of importing this folder, its generic entry
  in `ballware-docs/scripts/fetch-openapi.mjs:13` must be extended from
  `docs: ["generic", "service", "schema"]` to `docs: ["generic", "meta", "service", "schema"]`,
  otherwise the `meta` document stays invisible to the docs site.
- The `openIdConnectUrl` in the snapshots (`https://localhost/.well-known/openid-configuration`) is a
  placeholder produced by the Swagger environment, not a real endpoint
  ([openapi/README.md](openapi/README.md#why-aspnetcore_environmentswagger)).
